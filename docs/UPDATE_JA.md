# 1.0.0 / 1.0.1 / 1.1.0-beta.1 / 1.1.0-beta.2からの更新

**拡張機能を削除せず、以前Chromeに登録した `extension` フォルダを同じパスで更新します。** 新しいフォルダを別の拡張機能として追加すると、別のIDと保存領域になる場合があります。

1. 旧版の一覧から「バックアップ」を保存します。複数案件がある場合は案件ごとに保存してください。
2. `chrome://extensions` で現在の拡張機能IDと読み込み元のパスを控えます。
3. Chromeを終了します。
4. 新しいZIPを解凍して `ReviewDesk_1.1.0-beta.3` をDownloadsに置いた場合、次を実行します。

```bash
bash "$HOME/Downloads/ReviewDesk_1.1.0-beta.3/UPDATE_FROM_MAC.command"
```

5. 表示された選択画面で、**以前登録したフォルダ**を選びます。今回の新しいフォルダではありません。
6. Chromeを起動し、拡張機能の再読み込みを押します。バージョン1.1.0.3、詳細のバージョン名1.1.0-beta.3、拡張機能IDが以前と同じであることを確認します。
7. 対象Webページも再読み込みします。以前の案件・指摘番号・画像が残っていることを確認してください。

Python 3.9以上が必要です。コマンドは既知の1.0.0/1.0.1/1.1.0-beta.1/1.1.0-beta.2ファイルとの完全一致と新配布物のSHA-256を確認し、元コードを隣の `ReviewDesk_code_backup_.../extension` に退避します。保存済みメモのChromeデータ領域にはアクセスしません。独自編集や未知のファイルがあれば停止します。バージョン番号だけで上書きを許可しません。

## 手動で更新する場合

Pythonがない場合も、バックアップとChrome終了は同じです。登録済み `extension` を**同じ名前・同じ場所に戻せる形で**別名に退避し、新版 `extension` を元のパスへ置いてください。登録を削除・新規追加せず、Chromeの再読み込みを使います。独自編集がある場合は機械的に置き換えず比較してください。

この手動手順にはコマンドの自動照合・失敗時復旧がありません。ファイルの取り違えが心配な場合はPythonの更新手順を使ってください。

## 戻す場合

Chromeを終了し、新版コードを別名で保管してから、退避した旧 `extension` を登録済みの元のパスへ戻します。Chromeで再読み込みしてください。DB名・バージョン・ストアは維持しています。ただし旧版は新しい役割や確認者等を理解しないため、**戻す前に新版でもバックアップ**してください。旧版による新項目の編集まで互換保証するものではありません。

## パネルを開けない場合

「準備をやり直す」を1回試します。更新直後のWebページは必ず再読み込みしてください。解消しない場合はエラーコード、Chrome/macOSのバージョン、操作を始めた場所だけを報告してください。実顧客の画面や認証情報は報告に添付しないでください。

この版は、起動失敗時の操作抑止・原因表示・再試行を維持し、DBが開かない場合のタイムアウトと復帰を追加しています。以前のMacで初回読み込みが停止した原因を特定した、という意味ではありません。
