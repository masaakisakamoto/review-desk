# ポートフォリオ用原稿

## 短い紹介

**Review Desk — 打ち合わせを、画像付きの修正依頼に。**

Webサイトを一緒に見ながら、「この文章を変えたい」「この画像を見直したい」を、その場所の記録として残すChrome拡張機能です。相談中の意見と修正が決まった内容を分け、人にもAIにも渡せるファイルにまとめます。修正後も同じ指摘番号で画像と確認結果を残せます。記録は端末内に保存し、共有するときだけ書き出します。

## 紹介ページの本文

### 出発点

実際のスタッフとの打ち合わせで、画面を見ながら出た話を、その後の実装依頼へ整理する必要がありました。「どの画面の、どの部分か」「まだ相談なのか、修正が決まったのか」「直した後に確認したか」を、会話とは別に追える形にしたいと考えました。

### 設計を選んだ理由

画面への注釈やAIへの引き渡しには、すでに優れた既存例があります。BugHerd、Marker.io、MarkLayer、Agentationを公式資料で比較し、Review Deskでは一緒に画面を見る小さな打ち合わせに集中しました。利用者登録や共有サーバーを前提にせず、記録と判断を端末に残し、確定した内容だけを明示的に持ち出せる構成です。[比較と出典](RESEARCH.md)

### 使い方

対象をクリックするか、文字・範囲を選び、短くメモします。要相談・修正確定・保留を整理したら、画像、依頼文、対象情報をZIPへ。修正後は元の指摘に画像と確認結果を追加します。例として公開するのは、架空の展示サイトと模擬画像です。

### 品質の扱い

以前の版では、準備が整わない状態で操作すると、コメントパネルが空白になる問題が報告されました。受領した1.0.1では起動失敗時の復帰処理があり、その検証を再実行しました。今回のβ版ではDB接続の待機・復帰、未保存入力の保護、更新互換性、確認済み状態の扱い、書き出した画像へのリンクも検証しています。

模擬環境での成功と、実際のChromeでの動作は区別しています。この開発環境では拡張機能を導入して実タブを撮影する検証を完了できず、以前のMacで最初の読み込みが停止した原因も未特定です。実機検証が終わるまでは、その点を明示した試用候補として扱います。効率改善率や利用者数など、測っていない実績は掲載しません。

### 次の改善

まずMac Chromeでの一連の操作を確認します。その後、英語UI、共有前の情報除去、修正結果の取り込みを、利用者の実際の困りごとに応じて検討します。共同編集・音声動画・AIへの直接接続は、初回公開には含めません。

## 操作例

架空の「Fieldnotes Studio」のボタンを題材にします。実顧客のURL・画面・氏名・健康情報は使用しません。

| 指摘   | 打ち合わせ中                                               | 判断               | 次の操作                                     |
| ------ | ---------------------------------------------------------- | ------------------ | -------------------------------------------- |
| R-0001 | “Learn more”の行き先が曖昧。“Check availability”にしたい。 | 修正確定           | 未対応として依頼ZIPに含める。                |
| R-0002 | 写真を別案と比較して決めたい。                             | 要相談             | 相談のまま残す。依頼ZIPには含めない。        |
| R-0003 | 説明の余白は次回検討する。                                 | 保留               | 判断を後日に残す。                           |
| R-0004 | 見出しの確認例。                                           | 修正確定・確認済み | 全体の共有資料で、修正前後と確認メモを示す。 |

`examples/sample.review.json` を読み込むと、この4件を操作できます。`examples/request.zip` は1件の実装依頼、`examples/meeting.zip` は4件の共有資料です。模擬画像・模擬確認結果の表示を消して、実利用の証拠に見せないでください。

## 60秒デモ動画の構成案

| 時間    | 画面                                                 | ナレーション／字幕                                           |
| ------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| 0–8秒   | 架空サイトのボタンを指す。顧客情報なしのデモと表示。 | 「打ち合わせで出た『ここを変えたい』を、その場で残します。」 |
| 8–20秒  | 拡張機能を開き、文字指定 → メモ → 保存済み表示。     | 「場所と画面を記録。短いメモを添えます。」                   |
| 20–30秒 | R-0001を修正確定、別の指摘を要相談・保留にする。     | 「決まったことと、まだ決めていないことを分けます。」         |
| 30–42秒 | 書き出しプレビュー → ZIP → REQUEST.mdとHTML。        | 「確定した未対応の項目だけを、人やAIへ渡せる形に。」         |
| 42–54秒 | 同じ指摘の前後画像、確認メモ、確認済み。             | 「直した後も、同じ番号で確かめます。」                       |
| 54–60秒 | 製品名と「端末内保存・明示的な共有・MIT」の字幕。    | 「Review Desk。打ち合わせを、次の修正へ。」                  |

これは撮影構成案で、完成動画ではありません。拡張機能での実撮影が未検証の間は、模擬モードの映像を本番操作として説明しません。公開前に架空サイト上で実際のChrome操作を録画し、ブラウザの個人情報やダウンロード履歴が映らないよう確認します。
